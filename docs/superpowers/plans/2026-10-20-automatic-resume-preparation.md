# Automatic Resume Preparation and Final Review Queue Implementation Plan

> **For agentic workers:** Execute task-by-task with focused red/green checks. This is a planning handoff, not implementation authorization beyond the user's approved task. Writing-plans skill was used; source code is intentionally not included.

**Goal:** Selected jobs automatically reach independently verified PDFs through conservative repairs and necessary, scoped questions, then receive separate, exact-version human approval in a resume-first review queue.

**Architecture:** Extend the existing SQLite jobs lifecycle, immutable snapshots, proposal/base overlays, semantic checks, checked renderer and artifact approval. Add a durable selected-batch coordinator and job-local repair/question history; keep queue navigation separate from preparation and approval. Keep pure policy/projection functions in core, persistence/scheduling/tool execution in CLI, and presentation in UI.

**Tech stack:** TypeScript, Zod, better-sqlite3, existing Hono HTTP runtime (not a new Express server), React/Vite, Vitest, Playwright, real LaTeX/Poppler PDF verification.

## Existing behavior and integration points verified by reading

- `packages/cli/src/jobs/preparation.ts` already checkpoints preflight/analysis/alignment/proposals/brief/deslop/compile/verify, inventories facts and publishes via `checkedRender`. It stops on non-ready proposals and certain recovered output; it has no conservative repair loop. Schema-output retries are not the required transient retry.
- `service.ts`/`worker.ts`/`repository.ts` use attempts, receipts, owner fences and one active worker per workspace. Admission/continuation currently throws on contention. Preserve that concurrency limit; enqueue selected work instead of removing the unique index. A question must release the active attempt/slot.
- `runtime.ts` currently captures policy with four generation calls and zero repairs/retries. `semantic-repository.ts` counts semantic calls separately. A new automatic cycle must account for both, not quietly exceed the captured policy or reset counters on each question/refresh.
- `semantic-service.ts` checks immutable exact quotations and caches results. Retrieval currently ranks passage text; add explicit citations and work context before relying on aliases. `unavailable` fallback facts are not evidence of factual uncertainty. `sameFact` compares work identity, predicate and qualifiers; preserve this restriction across jobs.
- `proposal-service.ts` supports revisioned overlays, input guards, source-bound groundings, corrections and exact-ready continuation. Its public save path records human provenance and can remember corpus updates: automatic repair needs a separate worker-authority path, never a call pretending to be a human or requesting `remember`.
- `draft-finalization.ts` separates unrestricted draft persistence from checked publication and checks candidate/context/parent bindings. It currently expects a parent artifact; initial preparation cannot simply be routed through its manual-parent path.
- `JobResumeReview.tsx`: prominent real validated page images, PDF fallback/open link, historical-version selection and fingerprint-bound approval. `JobResumeDetails.tsx`: one secondary view at a time, menu keyboard navigation, Back to resume restores Details focus. Reuse this presentation rather than adding an operational wizard or a competing preview.
- `JobFacts.tsx`: precise passage/source excerpts, scoped job-local confirmation and dated contradiction correction, preserved local answer text; the next editor remains enabled while prior checks refresh. Extend rather than regress it. Do not expose tool outages as confirmation requests.
- Existing `PdfVerifier` already normalizes curly/straight quotes while preserving words and checks page count, complete expected text and actual PNG previews. Keep it strict; passing model/renderer labels alone cannot certify a PDF.
- Read focused existing tests: core `job-preparation.test.ts`; CLI `jobs-worker.test.ts`, `job-semantic-service.test.ts`, `job-artifacts.test.ts`, `job-checked-render.test.ts`; UI `job-facts.test.tsx`, `job-resume-details.test.tsx`, `job-draft-actions.test.tsx` and the relevant starting portion of `jobs-ui.test.tsx`. Read full adjacent tests before modifying their subjects, especially proposal-service, exports, semantic-evidence and draft checks. Existing fixture helpers are preferable to duplicated setup.
- Existing disposable browser pattern: `scripts/run-resume-finalization-walkthrough.mjs`, `resume-finalization-evidence.mjs`, `resume-finalization-inspection.mjs`; borrow identity/trace principles, not its one-job fixture or fake PDF bytes used by unit tests.
