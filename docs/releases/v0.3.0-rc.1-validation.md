## Standards review

An independent read-only review found a capture correctness defect: a long
navigation shell could satisfy the browser's text-length readiness condition
before the job arrived. A follow-up reproduction showed a title-first shell
had the same problem. The old test assertion matched an H1 inside a script
literal, so it did not prove that the actual rendered posting was captured.

These findings are resolved in the feature commit. Extraction rejects busy,
loading-only, and title-only content when no usable structured description is
available. Browser capture polls actual extraction, requires a title or
discovery result, and retains an extraction failure if rendering stays
incomplete. Tests assert the extracted role and actual description, not a
substring of script source. The incomplete-render error also keeps its
`extraction_failed` diagnostic instead of becoming a network error.

The reviewer rechecked both corrections and ran the 12 browser tests with
zero failures. No remaining blocker was reported from those findings, and no
additional blocking security defect was found in the inspected capture path.
This was a focused review, not an exhaustive audit of all 140 files changed
across the preceding 28 commits.

## Spec review

The independent spec review confirmed two outstanding P1 acceptance gaps:

- [SL-BUG-002](../implementation/sentilink-followups/bugs/sl-bug-002-skills-operation-contract.md):
  fresh runner output does not carry the before/result skills intent expected
  by the optional domain checks. A prune can still remove the intended retained
  skills while displaying a contradictory After. The unit test manually
  supplying intent fields does not exercise the real runner contract.
- [SL-FEAT-001](../implementation/sentilink-followups/features/sl-feat-001-skills-review.md):
  unified review inventories summary/employment passages but cannot select the
  skills proposal's editor. A direct component test bypasses that broken path.
  The Changes display also uses free-text After rather than the applied list.

Both were observed in the
[Shutterfly walkthrough](../shutterfly-live-job-attempt-2026-11-09.md).
They are not resolved by successful URL capture or a green test suite. Stable
release notes must not claim that all SentiLink follow-ups are complete.

The review also reproduced an HTTP 200 semantic loading shell bypassing
browser recovery. That capture finding is resolved by the readiness changes
and regression fixtures above. No material scope creep was identified.

## Validation

The final candidate is built and tested with source held unchanged. Build,
test, and live-capture receipts are under
`walkthrough-output/release-review-2026-11-10/`. The CLI reports
`featherduster/0.3.0-rc.1` on Windows x64 with Node v24.14.0.

The focused capture run passed 75 checks across four files. It covers status
retention, browser and paste recovery, persisted history, private destinations,
DNS pinning, real Chromium redirects, delayed descriptions, incomplete
rendering, and preview labels. The independent browser-only rerun passed all
12 checks. Earlier exploratory tests caught the new shell regressions; those
failures were corrected rather than removed or marked skipped.

The final `npm run build` passed across all three packages. Vite retained its
existing warning about a JavaScript chunk exceeding 500 kB.

The full `npm test` run completed in 271.96 seconds with 1,805 passed, one
skipped, and one failed test across 152 files. The failure was a 20-second
timeout in `packages/cli/tests/automatic-preparation.test.ts`, in the seven-job
selection/order/replay scenario. Its timeout and assertions were not relaxed.
The full-suite gate is failed; focused green runs do not override that result.

An isolated rerun reproduced the seven-job scenario's readiness failure:
only six jobs were ready within its 15-second wait. The other two tests in
that file passed. This is not dismissed as a transient suite-load timeout;
its cause remains unresolved and publication is held. Both runs' raw logs and
exit statuses are retained with the private validation receipts.

A fresh disposable live capture against the supplied Shutterfly URL succeeded:
the direct request returned 403, the browser captured the correct role and
5,567 description characters in 9,229 ms, and no job was saved or prepared in
the user's workspace. This verifies current capture recovery, not the broader
automatic-preparation scenario that timed out.
